后端接口文档
==============

概述
---
- 公共前缀：`/api`
- 返回统一格式：
  ```json
  {
    "code": 0,
    "message": "success",
    "data": ...
  }
  ```
- 分页列表返回 `data` 结构为：
  ```json
  {
    "items": [...],
    "meta": {
      "page": 1,
      "limit": 10,
      "total": 100
    }
  }
  ```
- 所有写操作或用户敏感操作需要登录，默认通过 `Authorization: Bearer <token>` 传递。
- 上传文件接口使用 `multipart/form-data`，字段名为 `file`。

认证与用户
---
- `POST /api/auth/register`
  - 注册新用户
  - body: `{ username, password, nickname?, email?, phone?, avatar? }`

- `POST /api/auth/login`
  - 登录
  - body: `{ username, password }`
  - 返回 token

- `GET /api/auth/me`
  - 获取当前登录用户信息
  - 需要登录

- `PUT /api/auth/me`
  - 更新当前用户资料
  - body: `{ nickname?, avatar?, phone?, email? }`
  - 需要登录

- `POST /api/auth/change-password`
  - 修改密码
  - body: `{ current_password, new_password }`
  - 需要登录

角色申请与审批
---
- `POST /api/auth/role-request`
  - 提交身份/角色申请
  - body: `{ role, reason? }`
  - 需要登录

- `GET /api/auth/role-requests`
  - 查看角色申请列表
  - 仅 `admin` / `super_admin`

- `POST /api/auth/role-requests/:id/approve`
  - 批准角色申请
  - 仅 `admin` / `super_admin`

- `POST /api/auth/role-requests/:id/reject`
  - 拒绝角色申请
  - 仅 `admin` / `super_admin`

用户查询
---
- `GET /api/users`
  - 查询用户列表
  - 可按 `role`、`status` 等筛选

- `GET /api/users/:id`
  - 获取单个用户详情

管理员功能
---
- `GET /api/admin/users`
  - 管理员查看注册用户列表
  - 仅 `admin` / `super_admin`

- `PUT /api/admin/users/:id/active`
  - 启用或禁用用户
  - body: `{ is_active: bool }`
  - 仅 `admin` / `super_admin`

- `PUT /api/admin/users/:id/role`
  - 修改用户角色
  - body: `{ role: "student|mentor|investor|partner|team|admin|super_admin" }`
  - 仅 `admin` / `super_admin`

- `POST /api/admin/users/:id/reset-role-request`
  - 重置用户角色申请状态
  - 仅 `admin` / `super_admin`

超级管理员功能
---
- `GET /api/admin/admins`
  - 查看所有管理员账号
  - 仅 `super_admin`

- `POST /api/admin/admins/promote`
  - 提升用户为管理员
  - body: `{ user_id }`
  - 仅 `super_admin`

- `POST /api/admin/admins/demote`
  - 撤销管理员权限
  - body: `{ user_id }`
  - 仅 `super_admin`

文件上传
---
- `POST /api/uploads`
  - 上传文件
  - `multipart/form-data`
  - 字段名：`file`
  - 返回示例： `{ data: { url } }`
  - 上传后可通过 `/uploads/<filename>` 访问

创业申请
---
- `GET /api/applications`
  - 申请列表
  - 支持 `page`, `limit`
  - 管理员可查看全部，普通用户仅查看自己的申请

- `POST /api/applications`
  - 创建申请

- `GET /api/applications/:id`
  - 获取申请详情

- `PUT /api/applications/:id`
  - 更新申请

- `DELETE /api/applications/:id`
  - 删除申请

- `POST /api/applications/:id/submit`
  - 提交申请

- `POST /api/applications/:id/approve`
  - 审批申请
  - 仅 `admin` / `super_admin`

- `POST /api/applications/:id/reject`
  - 拒绝申请
  - 仅 `admin` / `super_admin`

团队与成员
---
- `GET /api/teams`
  - 团队列表
  - 支持 `page`, `limit`, `status`

- `GET /api/teams/:id`
  - 团队详情

- `GET /api/teams/my/members`
  - 获取我所属团队的成员信息
  - 需要登录（team_owner 或 team_member）

- `POST /api/teams`
  - 创建团队
  - 需要登录

- `PUT /api/teams/:id`
  - 更新团队
  - 仅团队 owner 或 admin

- `DELETE /api/teams/:id`
  - 删除/解散团队
  - 仅团队 owner、admin 或 super_admin
  - 解散时会将所有成员（包括 owner）角色重置为 student

- `GET /api/teams/:id/members`
  - 团队成员列表

- `POST /api/teams/:id/members`
  - 添加成员
  - 仅团队 owner 或 admin

- `DELETE /api/teams/:id/members/:user_id`
  - 移除成员
  - 仅团队 owner、admin 或本人

- `POST /api/teams/:id/invite`
  - 邀请用户加入团队

- `GET /api/teams/:id/invitations`
  - 邀请列表

- `POST /api/teams/:id/invitations/:invite_id/accept`
  - 接受邀请

- `POST /api/teams/:id/invitations/:invite_id/reject`
  - 拒绝邀请

- `POST /api/teams/:id/join-requests`
  - 申请加入团队

- `GET /api/teams/:id/join-requests`
  - 查看加入申请

- `POST /api/teams/:id/join-requests/:request_id/approve`
  - 批准加入申请

- `POST /api/teams/:id/join-requests/:request_id/reject`
  - 拒绝加入申请

- `POST /api/teams/:id/transfer-owner`
  - 转移团队所有权
  - body: `{ new_owner_id }`

- `POST /api/teams/:id/leave`
  - 团队成员主动退出团队
  - 仅 team_member 角色
  - 退出时会将用户角色重置为 student，并清理该用户在该团队的所有招募申请记录

- `POST /api/teams/:id/approve`
  - 审批团队
  - 仅 `admin` / `super_admin`

- `POST /api/teams/:id/reject`
  - 拒绝团队
  - 仅 `admin` / `super_admin`

项目

- `POST /api/projects/:id/connection-requests`

- `POST /api/projects/:id/connection-requests/:request_id/accept`

- `POST /api/projects/:id/connection-requests/:request_id/reject`

招募
---
- `GET /api/recruitments`
  - 招募列表
  - 支持 `page`, `limit`, `status`
  - 团队负责人可通过 `my=true` 查看自己团队的招募
  - **自动截止**：查询时会自动将超过 deadline 的 active 招募标记为 invalid

- `GET /api/recruitments/:id`
  - 招募详情
  - 如果招募已超期，会自动更新状态为 invalid

- `POST /api/recruitments`
  - 创建招募
  - 仅 team_owner 且团队已认证

- `PUT /api/recruitments/:id`
  - 更新招募
  - 仅团队 owner

- `DELETE /api/recruitments/:id`
  - 删除招募
  - 仅团队 owner

- `POST /api/recruitments/:id/solve`
  - 标记招募完成
  - 仅团队 owner 或 admin

- `POST /api/recruitments/:id/invalidate`
  - 作废招募
  - 仅团队 owner 或 admin

- `POST /api/recruitments/:id/apply`
  - 申请招募职位
  - body: `{ cover_letter, resume? }`

- `GET /api/recruitments/:id/responses`
  - 查看招募的所有申请
  - 仅团队 owner 或 admin

- `POST /api/recruitments/:id/responses/:response_id/accept`
  - 通过申请
  - 通过后用户会成为团队成员（role 变更为 team_member）
  - 仅团队 owner 或 admin

- `POST /api/recruitments/:id/responses/:response_id/reject`
  - 拒绝申请
  - 仅团队 owner 或 admin

补充说明
---
- 公开项目接口无需登录：`GET /api/projects`、`GET /api/projects/:id`。
- 图片与文件上传后的访问地址统一以 `/uploads/<filename>` 形式暴露。
- 开发环境下如果前端报跨域，请检查后端 `CORSOrigin` 配置。
- `super_admin` 拥有所有 `admin` 权限，并可管理管理员账号。

用户角色说明
---
- `student`：学生（默认角色）
- `team_owner`：团队负责人
- `team_member`：团队成员
- `investor`：投资人
- `mentor`：校外导师
- `partner`：资源方
- `admin`：管理员
- `super_admin`：超级管理员

认证策略
---
- 前端只存储 JWT token 到 localStorage
- 用户信息通过 `/api/auth/me` 接口获取
- 不将 user 对象存储到 localStorage，避免数据不一致

自动截止机制
---
- 招募查询时（`GET /api/recruitments` 和 `GET /api/recruitments/:id`）会自动检查
- 超过 `deadline` 且状态为 `active` 的招募会被自动标记为 `invalid`
- 无需定时任务，实时生效

数据一致性
---
- 解散团队时：
  - 所有成员（包括 owner）角色重置为 `student`
  - 删除团队相关的所有数据（projects、recruitments、responses等）
  - 遵循子表优先删除原则，避免外键约束错误
  
- 退出团队时：
  - 成员角色重置为 `student`
  - 清理该用户在该团队的所有招募申请记录
  - 从 `team_members` 表中删除记录
